01

Introduction and scope

This policy describes how the Virendra AI Studio application handles information when it is operated by its owner or authorized users. It is maintained by Virendra Kumar. The GitHub Pages website is a separate, static information site; it does not host the private dashboard or FastAPI backend and is not configured with analytics or advertising scripts.

The application is software that an operator runs and configures. Where it runs, which database and storage it uses, and which optional integrations are enabled affect how information is handled. This policy describes the behavior implemented in the project; it does not claim Google approval or certification.

02

Application architecture

The project includes a FastAPI backend and a browser dashboard. Users authenticate to the backend with local application accounts. The backend uses the configured database and can store generated video and subtitle files either on its local filesystem or in an operator-configured Azure Blob Storage account.

This public website is not the application service. The developer does not receive application data merely because someone visits this static project site.

Information the application may handle

  • Account and sign-in data: usernames, password hashes, account role and status, session-version values, and hashed login rate-limit keys. Passwords are hashed by the app; the original password is not stored as an account field. Browser sessions use a signed session cookie.
  • Content data: topics, source labels, generated scripts, SEO titles and descriptions, hashtags, workflow status, approval/publishing state, and file references.
  • Optional metrics: analytics and learning-signal fields entered by a user, such as views, click-through rate, retention, RPM, keywords, or preferred content styles.
  • Media: MP4 videos and SRT subtitles produced by the local renderer, plus any media references saved to the database.
03

Google OAuth and YouTube Data API

YouTube access is optional. The operator starts a Google OAuth flow using a Desktop-app client. The application requests these exact scopes:

  • https://www.googleapis.com/auth/youtube.uploadUpload videos to the authorized YouTube account.
  • https://www.googleapis.com/auth/youtube.readonlyRead YouTube account/channel information, including the authenticated channel.

After authorization, the app requests the authenticated channel's name and ID for display in the local setup output. It does not request the YouTube Analytics API scope. When an upload is made, Google receives the video file and its metadata (such as title, description, tags, category, and visibility) to process the request. The app processes the API response to update upload state; the daily workflow may write the returned video ID to application logs.

Tokens and channel information

The OAuth credential JSON is written to the file path configured by the operator (by default, youtube_token.json) on the machine running the OAuth helper/backend. The helper sets restrictive file permissions on platforms that support them. The file can include an access token and, when Google issues one, a refresh token. The app reads that file to call Google's API. Protect the host, filesystem backups, and credential file; the app does not encrypt this token file itself.

The channel name and ID are printed to the local setup console to let the operator confirm the account. The application does not maintain a separate channel-profile table. Google handles OAuth authorization and token operations under Google's terms and privacy practices.

More detail is available in the YouTube API Disclosure.

04

AI processing and other integrations

OpenAI

If an operator configures an OpenAI API key, the regular script-generation request sends the topic and associated prompt to the OpenAI API. The SEO request sends the topic and its prompt. The application has a built-in local template fallback for regular script/SEO generation when AI is unavailable. The optional daily news workflow sends selected RSS headlines and excerpts to OpenAI to produce a Hindi summary when that feature is enabled. Video narration itself uses locally installed speech and media tools; it is not generated by the OpenAI integration described here.

OpenAI processes API requests under the account, service terms, and data controls applicable to the operator. This project does not configure or guarantee a particular provider retention or training setting. Review OpenAI's current terms and settings before sending personal, confidential, or otherwise sensitive information.

Other connected services

When configured and used, YouTube receives upload requests and associated media/metadata. Optional Instagram, Facebook, or Telegram publishing integrations send the content needed to publish to the selected service, using credentials supplied by the operator. Azure Blob Storage receives generated media when configured. The daily news workflow makes requests to publisher RSS feeds and uses the returned headlines, excerpts, and source links. These services each have their own terms and privacy practices. No optional integration is represented as active by default unless the operator configures it.

05

Database, storage and retention

Application records are stored in the database selected by the operator. Generated media is stored on the backend's generated-media filesystem by default, or in the configured Azure Blob Storage account when that option is enabled. Access controls, backups, region, and retention for those services depend on the operator's deployment and configuration.

The project does not define a universal retention period or automatic cleanup schedule for application database records, OAuth token files, or stored media. The operator is responsible for protecting backups and setting retention appropriate to their deployment. Replacing a generated video may remove an older managed media file, but this is not a general account or content deletion feature.

Do not assume that all information remains on one device: configured external AI, Google, storage, or publishing services receive the data needed to perform the requested operation.

06

Your choices and data deletion

  • Disconnect YouTube: revoke Virendra AI Studio's access from your Google Account third-party connections. Revocation prevents further authorized API access, subject to Google's processing. Then stop any enabled scheduler and securely remove the local OAuth token file from the configured host path. Revocation does not itself delete videos already uploaded to YouTube.
  • Stop optional processing: the operator can stop using an integration or remove its configuration. The daily public scheduler is off by default; set DAILY_NEWS_AUTOPUBLISH_ENABLED=false and stop/restart the backend to ensure it is not running.
  • Delete application data: the project currently has no end-user interface for deleting accounts or content and no configured retention deadline. Ask the application operator to remove relevant database records, local files or Azure blobs, and backups using the applicable deployment's procedures. Removing a database record alone may not remove a media object or copies retained in backups.
  • Delete Google data: manage content already uploaded, including its deletion, in YouTube Studio. Google may retain information as described in Google's own policies.

For questions about an installation, contact the person operating that instance. For questions about this project policy, contact the developer listed below.

07

Security, children and policy limits

The project includes password hashing, session controls, login-attempt limiting, and local OAuth token-file permission setting. These measures do not guarantee security. Operators remain responsible for HTTPS, host and database access, backups, secrets, dependency updates, and securing any third-party credentials. Avoid placing sensitive information in content prompts.

Virendra AI Studio is a general creator tool and is not designed to collect personal information from children. Operators should not use it to knowingly collect children's personal information in violation of applicable law or provider terms.

The application can be modified or deployed differently by its operator. This policy cannot promise behaviors or retention controls that have not been implemented in a particular deployment.
